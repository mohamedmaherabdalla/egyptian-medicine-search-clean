### Root cause classification

**Oracle/protocol defect; no algorithm change justified.**

The first composed-collision oracle grouped every catalog family that could
generate the same query through *any* two declared transformations. That made
families look equally supported even when they required different operation
signatures, mappings, channels, and costs. For example, sharing a final query
through two ordinary edits is not equivalent evidence to sharing it through a
specific low-cost grapheme pair. Requiring every such family in the public top
20 was therefore not a valid hard ambiguity contract.

### Protocol repair

1. Hard composed-ambiguity rows now group by the complete declared operation
   fingerprint: query, composition signature, exact mapping tuple, and channel
   tuple.
2. The broader query-level collision rows remain frozen in a separate
   `name_reading_cross_channel_diagnostics.csv` cohort. Their relevant-family
   recall is reported, but it is not mislabelled as an equal-evidence safety
   gate.
3. Atomic accuracy, composed accuracy, atomic ambiguity, literal exact-name,
   and source-boundary methods were not weakened.
4. No Algorithm 5, Algorithm 6, product-reranker, API, or catalog source was
   changed for this correction.

### Second diagnosis

This run exposed one algorithm gap and one remaining oracle gap.

1. Algorithm 5 could look up an exact family after one phonetic collapse, but
   it could not retrieve a family that required `CKS->X` or `GHT->T` plus one
   ordinary insertion, deletion, substitution, or transposition.
2. Independently reversing the declared operations showed that `OGHTA` also
   reaches YOTA at the same evidence fingerprint. The strict oracle was
   incomplete until all three families were recorded.

### Narrow runtime and oracle repair

- Only the long collapses `CKS->X` and `GHT->T` may compose with one ordinary
  edit.
- The character produced by the collapse is protected from that ordinary
  edit; query length is limited to 5--20; exact catalog lookup is required;
  and the complete exact-family set must contain at most four families.
- The evidence is scored with the existing bounded rescue machinery and is
  surfaced only in hidden tail slots. It never promotes itself to rank 1.
- Algorithm 6 protects these surfaced rows from consensus tail eviction.
- The generator now builds strict composed relevance independently by
  reversing the declared operations over the catalog, rather than trusting
  only sampled witnesses.

During focused verification, the first tail implementation incorrectly moved
already-visible evidence to the tail. `OGHTAL` consequently lost OTAL at rank
1. That implementation was rejected; the surfacer now reserves tail slots
only for hidden evidence and leaves existing ranking untouched.
