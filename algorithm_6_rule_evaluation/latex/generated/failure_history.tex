\paragraph{\texorpdfstring{\texttt{VG-MAN-POS-6301317104570E} - \texttt{PANA...OL}}{VG-MAN-POS-6301317104570E - PANA...OL}}\label{vg-man-pos-6301317104570e---panaol}

\begin{itemize}
\tightlist
\item
  Historical expectation: broad variant group \texttt{PANADOL}.
\item
  New exact-family evaluator observation: no exact \texttt{PANADOL} base appeared in
  the top 20.
\item
  Root cause: the historical test label was a broad group, not an exact base.
  The final catalog has ten exact base/head families satisfying the raw
  \texttt{PANA...OL} positional evidence; the API returns all ten. \texttt{PANADOL} itself is
  display/group metadata rather than one exact base family.
\item
  Resolution: re-oracle the row from catalog family/full-head surfaces and
  store all ten exact relevant keys. No algorithm change.
\end{itemize}

\paragraph{\texorpdfstring{\texttt{OCR-NONTRANS-IARDX-GARDX}}{OCR-NONTRANS-IARDX-GARDX}}\label{ocr-nontrans-iardx-gardx}

\begin{itemize}
\tightlist
\item
  Historical contract: direct variant generation must not compose \texttt{I-\textgreater{}E} and
  \texttt{E-\textgreater{}G} on the same original character.
\item
  Incorrect unified check: forbade ordinary search from returning \texttt{GARDX}.
\item
  Root cause: GARDX can be retrieved by unrelated ordinary similarity sources;
  that does not prove transitive grapheme generation.
\item
  Resolution: execute the source function
  \texttt{grapheme\_confusion\_variants("IARDX",\ max\_confusions=2)} and assert that its
  generated variant set excludes \texttt{GARDX}. No algorithm change.
\end{itemize}

\paragraph{Target-side alignment metrics (three rows)}\label{target-side-alignment-metrics-three-rows}

\begin{itemize}
\tightlist
\item
  \texttt{CLICY...\ -\textgreater{}\ DICYNONE} reported hidden/coverage \texttt{3/.625} instead of \texttt{4/.5}.
\item
  \texttt{BACTID...\ -\textgreater{}\ BACTICLOR} reported \texttt{3/.666667} instead of \texttt{2/.777778}.
\item
  \texttt{...TIDOR\ -\textgreater{}\ BACTICLOR} reported \texttt{4/.555556} instead of \texttt{3/.666667}.
\item
  Root cause: the implementation subtracted the raw observed-fragment length
  from the target length. Variable-length OCR rewrites (\texttt{CL\ \textless{}-\textgreater{}\ D}) change how
  many target characters the visible evidence consumes.
\item
  Algorithm fix: exact, grapheme, direct-confusion, and fuzzy matchers now
  return target-side alignment evidence. \texttt{hidden\_character\_count} and
  \texttt{visible\_coverage} are computed from consumed target spans. The regression
  suite asserts the exact three pairs, not merely \texttt{hidden\ \textgreater{}\ 0}.
\end{itemize}

\paragraph{Punctuation incorrectly activated shorthand (two rows)}\label{punctuation-incorrectly-activated-shorthand-two-rows}

\begin{itemize}
\tightlist
\item
  \texttt{PANA.DOL} and \texttt{PANA-DOL} were dispatched as visual gaps.
\item
  Root cause: the shorthand parser extracted alphabetic tokens from any
  punctuation-separated text, although the documented shorthand is
  whitespace-separated.
\item
  Algorithm fix: marker-free shorthand now requires a complete match of two to
  four whitespace-separated alphabetic tokens. Periods and hyphens retain
  ordinary spelling-query semantics.
\end{itemize}

\paragraph{Punctuation beside an edge marker changed its anchor (two rows)}\label{punctuation-beside-an-edge-marker-changed-its-anchor-two-rows}

\begin{itemize}
\tightlist
\item
  \texttt{(...TRIL} was interpreted as internal instead of leading and missed
  RIVOTRIL.
\item
  \texttt{RIVO...\ )} was interpreted as internal instead of trailing and missed
  RIVOTRIL.
\item
  Root cause: edge anchors were inferred from raw marker character offsets.
  Punctuation that compacts to no letters falsely counted as visible evidence.
\item
  Algorithm fix: anchors now derive from retained compact fragments on each
  side of the marker. Focused regressions include leading and trailing
  punctuation variants.
\end{itemize}

\paragraph{Marker-only confirmation expectation (one row)}\label{marker-only-confirmation-expectation-one-row}

\begin{itemize}
\tightlist
\item
  \texttt{...} correctly returned ordinary \texttt{no\_match} with zero rows, but the protocol
  incorrectly required response-level visual confirmation.
\item
  Root cause: the dataset generator applied the visual confirmation contract to
  every protocol row, including rows whose expected decision is explicitly
  \texttt{not\_visual\_gap}.
\item
  Evaluation fix: confirmation is required only when the expected decision is
  \texttt{visual\_gap\_matches}. The algorithm was not changed for this row.
\end{itemize}
