\section{Rule authority}

The implementation commit \texttt{d5b0e7e} and Rulebook Appendix 24 establish
the pre-repair behavior. The visual repair changes only eight visual functions:
\texttt{parse\_visual\_gap\_query}, target/grapheme alignment helpers, and
\texttt{visual\_gap\_matches}. Algorithm 5 remains byte-identical at SHA-256
\texttt{a8f040de...}. The full clean-set proof records this boundary explicitly.

\begin{methodbox}[title=Rule status vocabulary]
\textbf{Active} changes retrieval, scoring, order, filtering, or response.
\textbf{Guard} prevents an unsafe broad interpretation. \textbf{Diagnostic}
is computed but does not order results. \textbf{Disabled} is present behind an
inactive policy gate. \textbf{Inherited} comes from Algorithm 2/5.
\textbf{Browser fallback only} is not Python Algorithm 6 parity.
\end{methodbox}

\section{Generation principles}

\begin{enumerate}
\item \textbf{Freeze inputs before execution.} The generator reads the catalog,
source registries, and literal reviewed cases; it never reads algorithm output.
\item \textbf{Use stable selection.} SHA-256 over the dataset version, mode, and
exact family determines selection and the 80/20 family-stable development/holdout split.
\item \textbf{Label exact families independently.} The visual oracle enumerates
complete names and distinct family heads and stores every exact base satisfying
the ordered-fragment pattern. Broad \texttt{variant\_group} is display metadata,
not relevance.
\item \textbf{Preserve ambiguity.} Collision cases retain every exact relevant
family rather than forcing one source family to be ``correct.''
\item \textbf{Hash everything.} Dataset, generator, catalog, result, and raw
response hashes are stored in JSON manifests.
\item \textbf{Never delete a failure.} A label/evaluator defect is corrected
with an adjudication record; an algorithm defect becomes a permanent regression.
\end{enumerate}

\chapter{Visual-gap evaluation design}

\section{Why the previous smoke was insufficient}

The older generated smoke periodically sampled 64 \texttt{first3...last3}
patterns and scored broad variant groups. Twenty-two sampled rows came from
broad groups, so a sibling could satisfy the assertion while the exact source
base was absent. The new package replaces that label contract with exact-family
keys and a full relevance set computed before evaluation.

\section{Coverage matrix}

The protocol covers every accepted marker family (short/long dots, Unicode
ellipsis, star, question, underscore, and adjacent mixed runs), all four edge
modes, two through four visible fragments, five-fragment rejection, shorthand
versus exact multiword search, raw/fixed-grapheme/directional-confusion/fuzzy
stages, all shared operation budgets, repeated occurrences, exact-family
identity, large relevance sets, response confirmation, and loaded-catalog
performance.

\begin{methodbox}[title=Independent visual oracle]
For each generated pattern the generator searches compact complete-name and
distinct family-head surfaces with its own recursive ordered-fragment matcher.
An explicit marker consumes at least one target character; shorthand may join
at zero width. The generator does not call production visual parsing, matching,
ranking, or saved result files.
\end{methodbox}

\section{Acceptance gates}

Parser dispatch, exact-family identity, expected/forbidden family checks,
stage reasons, target hidden count/coverage fixtures, response/row confirmation,
and source-level non-transitivity are zero-tolerance. The heavy 24-character
query remains below two seconds and the direct pattern state never exceeds 512.
Development and holdout are reported separately; challenge regressions remain
a public engineering denominator, not an unbiased accuracy estimate.

\chapter{Protocol for adding a new rule}

\section{Required workflow}

\begin{enumerate}
\item assign an immutable rule ID and state whether it is active, a guard,
diagnostic, disabled, inherited, or browser-only;
\item define direction, scope, length/rank/cost thresholds, ambiguity behavior,
and the exact safety boundary before coding;
\item add positive, negative, equality-boundary, just-outside-boundary,
ambiguity/collision, and performance cases to development data;
\item freeze/hash the new denominator and record source/catalog identity;
\item execute and save every raw response before changing the algorithm;
\item classify each failure by normalization, parser, candidate generation,
alignment, rank/promotion, product admission, compatibility, hydration, UI, or
dataset/evaluator contract;
\item if source is wrong, add the failed row as a permanent regression and
implement the narrowest general fix; if the label is wrong, preserve the failed
run and document the independent adjudication;
\item rerun the focused suite and every shared downstream denominator;
\item require paired losses, candidate counts, confidence/confirmation,
runtime identity, and latency---not only aggregate accuracy;
\item update the registry, rulebook, manifests, and PDF in the same change.
\end{enumerate}

\begin{warningbox}[title=Holdout discipline]
Do not tune a threshold on holdout or reserve failures and then claim the same
partition is untouched. Preserve the result, promote the exposed case into the
next version's regression set, bump the dataset/protocol version, and evaluate
the next frozen component holdout.
\end{warningbox}

\section{Minimum downstream matrix}

\begin{itemize}
\item name/OCR change: focused OCR, visual if shared graphemes changed, fair 412,
clean affected/full equivalence, API confirmation;
\item visual change: 404 visual, ordinary exact-name guards, OCR, fair 412,
clean dispatch proof/full run, product visual integration, performance;
\item product-context change: 132 focused, strict 200-case selected-ID
evaluation, API product identity/hydration, browser normalization where shared;
\item API/UI change: runtime/health/search checks, response/row confirmation,
stable IDs, browser race/cache tests, and a rendered DOM check when available.
\end{itemize}
